# Canonical context projection v2.1 — source successor

This reviewed candidate corrects a demonstrated current capture blocker: one local materialized index title differed from its current owner-bound canonical record. All 80 records passed ownership/completion/version checks. The local index exactly matched its archived metadata, but one title projection was stale. Hash-only auditing found that field difference without exporting its text. The controlled attempt rejected at context capture before policy/producer/writeback; its exact inner code was not retained. This current mismatch is not asserted as conclusive historical failure attribution.

The existing private batch route now returns a bounded six-string canonical projection (stamp, title, emoji, category, segment count, overview) plus its digest and unchanged provenance pins, under response contract `ella-context-records-v2.1`. It adds no transcript field. These projection strings are private same-owner context data, not authorization or trusted instructions. Existing service authentication, subject namespace, target/runtime/source/attempt checks before and after reading are unchanged. The response cap is explicitly 256 KiB; deadlines, retries, provider and credentials are unchanged.

The host still validates the local index against its safe materialized CID hints, then uses every current canonical projection to rebuild the frozen model index. It omits no row and writes no workspace file. A derived revision binds the previous raw snapshot revision and new canonical index digest. The sidecar retains the original identity/version/hash pins and canonical row digest, without projection bodies. Later source/version/deletion/owner/runtime/consent/attempt changes still reject; unrelated index append/eviction cannot replace captured input. The previous disclosed current-index-read availability limitation remains.

Fixed-vocabulary diagnostic logging is also added at the captured-context rejection boundary: only a literal allowlisted code, source-ID hash and attempt hash may be emitted. Private response/exception bodies, transcripts, prompts and user identifiers are excluded. Logging failure cannot replace the original rejection, and generic missing-header rejection remains diagnosable.

Actual source qualification: 77 focused cases (40 backend, 3 logger, 34 host), with external authority/DB/HTTP leaves explicitly doubled. This includes inherited cases; do not add counts as independent coverage. The real production Python 3.11 interpreter imported the touched application modules with sockets blocked and zero network attempts. A real read-only owner-bound 80-record audit verified all projection hashes and rebuilt the actual host renderer's index with zero omissions: 36,231-byte index, 80,289-byte projection response, 2707 ms. No provider call or DB/workspace mutation occurred in that audit. This does not establish full active-attempt HTTP latency or enhanced writeback.

This publication is source evidence, **not rollout or enrichment success**. The already failed attempt stays quarantined and original transcript/stock data are preserved.
