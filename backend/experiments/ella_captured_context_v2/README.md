# Captured context v2 — reviewed source candidate

This candidate captures model input once for an existing authenticated attempt, then revalidates authority, consent, target source/version, protected files and every captured recent-record provenance tuple before reusing that input. Unrelated recent-index appends or rolling eviction do not rewrite the generator/verifier requests. Manifest and attempt digests are bound to the publication policy. They are integrity checks, not new authorization.

This is **not a deployment or enhanced-writeback success claim**. Legacy v1 callers retain their existing contract. Unknown/closed attempts and quarantined jobs are not rearmed. The model/provider, account mapping, credentials and existing deadlines are unchanged. A remaining fail-closed availability limitation is that the host still reads the current rolling-index file during validation, although it does not require its content to equal the captured index.

Exact executable source is retained with `.py.source` suffixes so repository formatting hooks cannot silently change deployment pins. The small shim mount excerpt uses existing gates; the full unrelated shared shim is excluded. `SOURCE.PINS.json` covers all included source bytes.

Focused actual results in the owner workspace: backend 56 scope/batch cases; independent controller fault fixtures additionally exercise success, rollback and foreign-path rejection. Host 24 existing manifest cases plus finite-header and real disposable filesystem controller cases. The fresh Linux production interpreter (3.11.0rc1) imported the complete touched application modules with sockets blocked, zero network attempts, registered new callback route and consistent real publication class identities. The existing host interpreter imported the actual helper closure with sockets blocked and its already-installed user-site dependency. A read-only smoke over the original account's 20 saved records passed real decryption, bounded decode and metadata projection in 2453 ms. It is not full authenticated HTTP or model/writeback proof.

The included test sources are review evidence, **not a self-contained portable suite**: they name the isolated owner's retained source closure, live-free fixtures and controller files outside this package. No claim is made that cloning this package alone executes those tests. Fixtures substitute external authority/DB/HTTP leaves explicitly; they do not establish real-provider behavior. Controller source and operational account packets are intentionally not published here.

Rollout must preserve closed claims, each quarantine and the existing execution hold, verify exact source/PID/state preimages, restart only the designated service, verify health/imports/auth rejection and roll back only owned file identities. A single eligible record with original-agent execution and canonical enhanced readback is required before backlog processing.
