# Versioned typed stock for completed-parent recovery

The old completed-parent admission calls the strict namespace JSON digest on decoded stock. An SDK timestamp makes that call raise `TypeError`. The new closed protocol `ella-completed-parent-typed-stock-v1` requires the historical display digest as an operator-bound pin and uses the existing typed decoded-stock recipe in both admission and source/callback checks. The protocol participates in the new namespace identity. Existing protocol recipes, global namespace digests, private allowlists and record08 certificates remain unchanged.

Nineteen focused offline cases passed: real admission/claim/begin/graph/server-callback composition against explicit fake storage and IO leaves; invalid old result preservation; changed source/owner/version rejection; actual public SDK timestamp type, precision, rendering-collision and lookalike cases. Tests show that SDK snapshot/deepcopy can already discard finer fractions. The typed recipe preserves available decoded values; it is not raw Firestore nanosecond integrity proof.

An isolated overlay loaded the candidate using the actual Python 3.11.0rc1 service environment, with all five forbidden-I/O counters zero and unchanged existing private dependencies. One inherited, source-pinned loopback IPv6 capability probe opened and closed; it is tracked separately from forbidden network access. There was no deployment, restart, live database write, model request or recovery admission. Fresh execution still needs guarded rollout, exact historical detachment/sync/provenance qualification and fresh source/authority/transaction preimages. The invalid retained output must not be reused. The existing original-owner OAuth Sol route and permissions do not change.

The `.py.source` files preserve exact reviewed inputs. Their retained harness and one exact-metadata assertion depend on internal evidence; this archive is not a standalone portable test package or permission to replay quarantines. No private certificates, prompt/source contents or live execution controllers are published here.
